## 답할 수 있게 된 프로젝트 질문 (PRD 8.4)
1. **'잘 맞아 보이는' 스킬이 실제로 이득을 주는가?** 이번 9개 과제에서는 **아니다.** 자동 호출 0회이고, 강제 호출해도 기능 차이가 없었으며, 비용은 약 30–45% 늘었다.
2. **스킬이 필요 없는 경우는 얼마나 되나?** 9개 중 9개에서 NO_SKILL로 충분했다(기능 기준). 선정기의 NO_SKILL 권장과 방향이 일치한다.
3. **선정 오류는 어디서 생기나?** 주로 **검색 풀**이다. 수집원에 웹 UI·접근성·리팩터링 같은 범용 스킬이 거의 없어, 차순위 후보가 과제와 무관했다. 순위 오류(RANKING 3건)는 감사로 재현했다.
4. **추가 비용이 정당한가?** 효과가 없으니 정당하지 않다(추정 비용 기준).
5. **다른 모델·환경에서 유지되나?** 미확인. haiku, Windows, 프로필 S 한 조건에서만 실행했다.

## 확정 불가 (일반화 보류)
- 표본: 팔당 n=1, 과제 9개, 모델 하나 → PRD 4.4 단계 1(시스템 검증)의 결론일 뿐이다. 우위나 열위를 주장하지 않는다.
- B 후보가 약했다(선정기 차순위). "좋은 스킬이 도움이 되는가"는 관련 스킬을 손으로 고른 비교(PRD 25.1 단계 1의 원래 설계)로 다시 확인해야 한다.
- 라벨 20개와 루브릭은 같은 모델 계열이 작성했다. 독립된 사람 평가자가 없다(PRD A.3). 그래서 **내부 예비 실험**이다.
- 비용은 Claude Code 클라이언트 추정치다(프로필 S).
